# FFUI v0.3.5

## English

This release makes the Linux AppImage start for users who did not build it. Apart from the toolchain update below, the application is unchanged from v0.3.4.

### Fixes

- Linux AppImage: the launcher wrapper inside the package was mode `0770` (executable by its owner and group only, not by others). Started the usual way the runtime's FUSE mount presents the files as owned by the user who started it, so it worked for the person who built it; mounted by another user - firejail, a root-mounted mount, or the AppImage catalog test - the launch failed with `Permission denied` on `AppRun.wrapped`. The Tauri 2.12 toolchain this build uses writes it as `0755`.

### Maintenance

- The Tauri toolchain moves to 2.12: CLI, Rust crates (`tauri`, `tauri-build`, plugins), the JS API and the JS plugins.
- Frontend and build dependencies were refreshed to their newest compatible releases; `sortablejs` typings now come from `@types/sortablejs` instead of a local declaration.

### Release process

- A release is published only after the uploaded AppImage passes an automated acceptance gate: structure and AppDir lint, world-readable/executable permissions read from the image itself, a real start as a non-owner under Xvfb, and finally the AppImageHub test harness (`code/worker.sh`) against the uploaded file.

## 中文

本版让 Linux AppImage 在**不是构建者本人**的用户下也能启动。除下面的工具链更新外，应用本身相对 v0.3.4 没有其它变化。

### 修复

- Linux AppImage：包内的启动器包装 `AppRun.wrapped` 权限是 `0770`（只有属主与同组可执行，其他用户不可执行）。常规启动时 runtime 的 FUSE 挂载会把这些文件显示为启动者所有，所以构建者本人怎么试都正常；一旦由别的用户挂载——firejail、root 挂载、或 AppImage 目录站的测试——启动就会在 `AppRun.wrapped` 上以 `Permission denied` 失败。本版采用的 Tauri 2.12 工具链会把它写成 `0755`。

### 维护

- Tauri 工具链升到 2.12：CLI、Rust crate（`tauri`、`tauri-build`、各插件）、JS API 与 JS 插件。
- 前端与构建依赖升到各自最新的兼容版本；`sortablejs` 的类型改用 `@types/sortablejs`，不再使用仓库内自写声明。

### 发布流程

- 只有上传的 AppImage 通过自动验收门禁后才会发布：结构与 AppDir lint、**从镜像本身读取**的其他用户可读/可执行权限、以非属主身份在 Xvfb 下真实启动出现窗口、以及最后对**已上传文件**运行 AppImageHub 的测试脚本（`code/worker.sh`）。
