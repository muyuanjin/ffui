# FFUI v0.3.6

## English

This release makes the queue explain itself when audio or image files are added, lets Media Info inspect audio, and makes the Linux AppImage updatable in place. The transcoding pipelines themselves are unchanged.

### New

- Media Info can inspect audio files, not only video and image files.
- The Linux AppImage embeds update information and ships a `.zsync` next to it, so AppImageUpdate and AppImageLauncher can update it in place and download only the changed blocks instead of the whole image. Check it with `./FFUI_0.3.6_amd64.AppImage --appimage-updateinfo`.

### Fixes

- Adding audio or image files to the queue - selecting them, dropping them, or adding a folder that contains them - now says that the queue transcodes video only and points at Batch Compress, instead of ignoring those files silently. The queue still transcodes video only: adding audio directly to the queue is not supported yet, and audio files belong to Batch Compress.

### Release process

- Publishing verifies the update signature against the AppImage that is actually shipped and keeps `latest.json` in sync with it, so a build whose in-app update would fail is no longer published.

## 中文

本版让队列在加入音频/图片时把原因说清楚、让媒体信息可以打开音频，并让 Linux AppImage 支持就地更新。转码管线本身没有变化。

### 新增

- 媒体信息可以打开音频文件，不再只支持视频与图片。
- Linux AppImage 内嵌更新信息并附带 `.zsync`，因此 AppImageUpdate、AppImageLauncher 可以就地更新，且只下载变化的区块，不再重新下载整个镜像。可用 `./FFUI_0.3.6_amd64.AppImage --appimage-updateinfo` 查看。

### 修复

- 把音频或图片加入队列时——无论是选中、拖入，还是添加一个包含它们的文件夹——现在会说明队列只处理视频，并指向批量压缩（Batch Compress），不再静默忽略这些文件。队列本身仍只处理视频：把音频直接加入队列暂不支持，音频文件属于批量压缩（Batch Compress）。

### 发布流程

- 发布时会核对更新签名与实际发布的 AppImage 是否相符，并同步 `latest.json`；应用内更新会失败的构建不会再被发布。
