# Meta Layer Guard

本技能保护层级隔离：把上层约束**转译**成下层结果，而不是把上层话语搬进产物。

## 使用门禁

以下任务在写入或交付前必须执行转译与自检：

- 从对话、日志、会话、评审记录或复盘中提炼规则、原则、文档、注释或 skill。
- 创建、修改或审查任何规则载体（长期规则文件、README、开发指南、规范文档、发布说明、`.agents/skills/**`）。
- 把某个工具、平台、产品或运行环境中的经验抽象成通用方法。
- 用户指出「泄露」「范畴混淆」「这不该写进产物」之后继续修改产物。
- 产物本身就是规则文档、流程文档或安装说明。

高风险场景下不要只在心里记住原则：先定义产物读者、产物层级、允许内容与禁止内容，再写入文件。

## 层级模型

- **系统层**：系统提示词、运行权限与不可覆盖规则。
- **规则层**：长期生效的项目规则、仓库约定与环境约束。
- **元技能层**：关于如何读取、选择、触发或解释技能的规则。
- **对话协商层**：用户与 agent 对目标、偏好、边界与实现方式的讨论。
- **执行过程层**：计划、工具调用、尝试、失败、验证与中间判断。
- **产物层**：用户真正要交付的文件、代码、文档、配置或其他成果。

高层内容可以**约束**低层产物，但不能原样泄露进产物层。

## 第一原则

执行指令，而不是抄写指令。

对话协商层给出修正时，产物层体现**修正后的结果**，不记录修正语句：

- 要求移除某段 → 产物中就没有那一段。
- 要求用某方案替换另一方案 → 产物直接采用替换后的方案。
- 要求避免某类写法 → 产物避开该写法，而不是写一条「避免该写法」的说明（除非产物本身就是规则文档）。

## 泄露识别

写入或交付前，检查产物里是否出现不属于产物层的痕迹：

- 对用户纠偏的复述（「按你的要求」「不要写」「改成」「你说过」）。
- 对 agent 行为的叙述（「我将」「我已经」「agent 应该先」）。
- 实现过程残留（临时方案、失败尝试、调试路线、中间计划）。
- 对上层规则的机械搬运（把系统提示词、长期规则或技能使用说明写进业务文档）。
- 安装或触发机制的混入（在不负责安装说明的产物里写某个规则载体怎么引入）。

产物本身就是规则、流程或安装说明时，可以写相关规则；但仍只写目标读者需要执行的**稳定规则**，不写协商过程。

## 常见失败模式与修复

### 来源词泄露

从具体来源提炼通用规则时，容易保留平台名、执行器名、模型名、会话名、路径或产品扩展名。
修复：判断它是否是目标读者必须执行的规则；不是就抽象成稳定概念（执行器、运行环境、规则载体），只是来源标记就删除。

### 规则载体泄露

读完某个 skill 或上层规则后，容易把「它来自哪里、如何触发、如何安装」写进业务产物。
修复：只保留该规则对产物的实际影响；载体信息留在安装或维护说明里。

### 修正语句泄露

用户纠偏后容易出现「按你的要求」「不要写某词」等痕迹。
修复：把纠偏转成删除、替换、收窄或重命名动作；产物只呈现修正后的结果。

### 验证误判

结构校验、格式校验或测试通过，不代表没有元泄露。
修复：把结构验证与语义泄露验证分开；高风险产物做关键词扫描加逐句语义检查；扫描通过后仍确认每句话对未来读者自然、必要、可执行。

### 机械替换残留

发现泄露后只替换词语，容易留下不自然短语、残缺语义或新的层级混淆。
修复：先判断泄露内容承担的结构功能，再重写相关句子或段落，然后确认上下文不依赖生成过程也能读懂。

### 经验教训过拟合

从失败案例补规则时，容易把单次事故的对象名、路径、命令与会话背景原样写进规则。
修复：把案例拆成「触发条件、错误动作、正确动作、验证方式」，删除具体来源与一次性细节。

## 转译步骤

1. 判断它属于哪一层。
2. 判断它对产物的真实影响：删除、替换、收窄、扩展、重命名、调整语气、改变流程，还是只影响 agent 行为。
3. 把影响直接应用到产物。
4. 从产物中移除协商痕迹与执行痕迹。
5. 只有产物目标本身需要说明规则时，才把规则写成面向未来读者的稳定表述。

## 写入前门禁

写入高风险产物前，先确定四项：

1. **产物读者**：未来谁会直接使用它。
2. **产物层级**：业务文档、规则文档、安装说明、代码、配置还是素材。
3. **允许内容**：读者执行所必须知道的稳定规则、步骤、字段、接口或约束。
4. **禁止内容**：来源平台、当前运行环境、临时凭据、对话修正、执行计划、失败尝试、工具调用、安装触发机制。

四项未完成时不要写入。

从失败复盘提炼规则时额外列出：失败模式（一般条件描述）、修复动作（未来可执行动作）、验证方式（检查方法）。

## 交付前自检

- 产物里的每句话，目标读者是否需要它才能正确使用产物？
- 有没有复述协商过程、评审意见或执行步骤？
- 有没有把「本文件从哪来、由谁维护、如何安装」写进不负责这些内容的产物？
- 规则类表述是否是面向未来的稳定规则，而不是一次事故的记述？
- 关键词扫描是否通过，且逐句语义检查也通过？
