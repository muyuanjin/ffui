# Trimming CoT Leakage

CoT 泄露指的是：文本的**视角是写作那次会话**，而不是仓库在 HEAD 的状态。它引用只有那次会话能看到的东西、叙述改动过程而不是当前状态，或在对一个已经离开的评审者辩解。

修复不等于删除：一句里若含事实性从句，先把每个从句改写成在 HEAD 独立成立的说法，再删掉周围的过程叙述；若整句不承载事实（编号、控制流叙述），直接删除。

## 唯一判据

对每一处可疑文本问：**一个在 HEAD 的读者，拿不到任何会话记录、评审讨论或未提交草稿，能否解析每个引用、验证每个主张？** 不能，就把仍然成立的事实改写成仓库视角并删掉其余；能，就不是本技能所指的泄露——但仍然要过第二条：在 README、文档、JSDoc 这类当前状态面上，可解析的改动史依旧是「叙述改动」，应写成当前行为。

## 分类

1. **只存在于某次会话的引用**——决策编号、审计条目号、某个未提交草稿的章节号、阶段标签。若该决定已有提交到仓库的归属，就按名字与路径引用它；否则删掉引用，把事实从句改写成独立成立。
2. **栈/PR 视角**——「本 PR 增加了」「上一个提交」。写机制或扩展点；延期的工作写成 `TODO` 或 issue 引用。
3. **改动叙述与版本印记**——「以前是」「不再」「旧的 X」，以及「本版」「这次改动」这类索引词。写当前行为；修好的回归写成现在时的反事实（「没有 X 时会 Y」），而不是仓库历史。
4. **评审编排**——「评审中否决」「评审者确认」「本条的第 5 版」。保留仍然成立的结论与理由作为事实，删掉谁说、什么时候。
5. **面向评审者的辩解**——注释为自己的正确性辩护。陈述让代码安全的**不变量**，或直接删除。
6. **复述与推导过程**——控制流叙述（「先 X 再 Y」）、测试走查、显然分支的证明。删除，只留不显然的契约或不变量。
7. **犹豫与计划残留**——「暂时应该够用」「大概没问题」这类没有标记的延期。提升为 `TODO`/`FIXME`，或改写成真实的边界。
8. **写作语言串味**——中文产物里混入英文工作语言片段，或反之。翻译或删除。

## 不算泄露的内容

- **可解析的 issue/PR 引用**：指向本仓库真实存在的 issue、PR，或带归属的 `TODO(名字):` 标记——在 HEAD 能查到，任何面都保留。
- **抑制理由**：lint 禁用理由、覆盖率忽略理由、空 `catch` 的说明——这些是必需文本；理由写错就改对，绝不要删。
- **现在时的反事实回归钉子**：「没有 X 时会 Y」。
- **实测边界**：「（实测：…）」用于校准常量，证据词是承重的。
- **运行期的新旧状态**：「旧连接排空后新连接才接受」是运行期生命周期，不是改动史。
- **外部引用**：标准章节号（RFC、规范）、外部设计文件里的名字——它们本就在仓库之外解析。
- **项目语气与体裁**：以「我们」指项目；变更记录类文档里的历史叙述。

## 工作流

1. **先划范围**：明确要审哪些面，跳过归档与第三方代码。生成物（截图、快照、生成目录）是派生物，不是文本目标：改生成它们的源，只有行为变更被授权时才重新生成。
2. **只读审计**：先用关键词粗筛（决策编号、`以前`/`不再`/`本版`、`评审`、控制流连接词等），但粗筛只是探针不是定义——务必再通读范围内最密的文本（模块 JSDoc、README、发布说明），因为粗筛一定会漏。
3. **按归属修**：能改源头就改源头（生成物的模板或源数据、类型的 JSDoc），再重新生成派生物；不要逐个手改派生物。
4. **改完复查**：重新通读改动段落，确认每句话在 HEAD 独立成立、不依赖写作过程，且没有为了「不像 CoT」而丢掉承重的事实。

## 与本仓库其它规则的关系

- 范畴混淆（把上层话语搬进产物）由 `.agents/skills/meta-layer-guard/SKILL.md` 负责；本技能只管「视角是会话而不是仓库」。
- 提交与推送的独立 review 门禁见 `docs/review-before-push.md`：它是流程约束，不因本技能而放宽。
